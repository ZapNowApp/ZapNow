## 1) วิธีเริ่มต้นใช้งาน

ต้องใช้ **Node.js** (มีในเครื่องแล้ว ไม่ต้องติดตั้งอะไรเพิ่ม)

```bash
cd sangkha-platform
node server.js
```

จากนั้นเปิดเบราว์เซอร์ไปที่:

```
http://127.0.0.1:4173
```

> ถ้าเซิร์ฟเวอร์ยังไม่รัน เปิดหน้านี้ไม่ได้ — ให้รันคำสั่งด้านบนก่อน
> เซิร์ฟเวอร์ใช้พอร์ต **4173** เสมอ (ไม่พึ่งตัวแปร PORT)

## 2.1) Design System กลาง (ทุกหน้าใช้ชุดเดียวกัน)

- **`styles/design-system.css`** — Design Token + สไตล์ Shared Component ทั้งหมด (สี `--primary-color`/`--accent`/`--success`/`--rider`/`--danger`/`--info`, เงา `--shadow-soft`/`--shadow`/`--shadow-lg`, รัศมี `--radius-sm`→`--radius-xl`/`--radius-pill`, ระยะห่าง `--space-1`→`--space-8`, ฟอนต์/อนิเมชัน) — **แก้ที่นี่ครั้งเดียว = ทุกหน้าเปลี่ยนตาม** — ทุกหน้าโหลดไฟล์นี้ก่อน CSS ของหน้าเสมอ
- **ธีมสี SangkhaFood (Theme 2026)** — พื้นหลังทั้งระบบ `--bg: #FFF8F0` / การ์ด `--card: #FFFFFF` / สีหลัก `--primary-color: #FF6B35` (+ `--primary-dark`/`--primary-soft`) / สีรอง `--secondary: #FFB703` / ข้อความ `--text: #222222` — **หัว gradient ส้ม→แอมเบอร์** (`.ds-header`/`.auth-header`/`.signup-header` — ตัวหนังสือขาว + ปุ่มกลับวงกลมขาว) / **เงาการ์ดนุ่มขึ้น** (`--shadow-soft`/`--shadow`/`--shadow-lg`) / **ปุ่มมุมโค้ง 16–20px** (`.ds-btn` 20px, ปุ่มหน้าต่าง ๆ 16px — ครอบ customer/dashboard/rider/admin/auth/login/signup — พร้อมแอนิเมชันกด scale) / หน้า login ใช้จานสีส้ม→แอมเบอร์ (เดิมแดง-ส้ม)
- **🌙 Dark Theme (ทั้งระบบ — แยกตามบทบาท/ผู้ใช้)** — สลับได้จาก **หน้าโปรไฟล์ลูกค้า (แท็บ บัญชี → "โหมดมืด")** — ทุกหน้า (`index`/`dashboard`/`rider`/`admin`/`login`/`signup`/`deals`/`deal`/`finance`) มี `<script>` เล็ก ๆ ใน `<head>` อ่านค่า**ก่อน CSS วาด** (กันจอวาบ) → ตั้ง `data-theme="dark"` บน `<html>` → `[data-theme="dark"]` ใน design-system.css สลับ token ทั้งชุด (bg `#17130E` / การ์ด `#242018` / ข้อความ `#F3EDE3` + สถานะ/เงาเข้ากับโหมดมืด) — **ธีมแยกรายคน: ลูกค้า → `sangkha-theme:customer:{เบอร์}` · ร้าน → `sangkha-theme:store:{id}` · ไรเดอร์ → `sangkha-theme:rider:{id}` · แอดมิน → `sangkha-theme:admin` · ยังไม่ล็อกอิน → `sangkha-theme` (เครื่อง)** — ลูกค้าสลับ dark **ไม่ไปเปลี่ยนหน้าหลังร้าน/ไรเดอร์/แอดมิน** (แต่ละบทบาทมีธีมของตัวเอง — ตรวจ session ใน head script ว่าใครกำลังใช้อยู่)
- **`components/`** — Shared Component (ใช้ผ่าน `window.UI.*` — คืน HTML string, รองรับ id/class เดิม):
  | ไฟล์ | component | ใช้กับ |
  |---|---|
  | `AppHeader.js` | `UI.AppHeader` | แถบบนสุดทุกหน้า (โลโก้/ชื่อ/subtitle/ป้ายสด/รูป) |
  | `UserCard.js` | `UI.UserCard` | การ์ดสรุปผู้ใช้/ร้าน/ไรเดอร์ (hero + สถิติ) |
  | `ActionCard.js` | `UI.ActionCard` | การ์ดปุ่มเมนูหลัก (ไอคอน/ชื่อ/คำอธิบาย) |
  | `Button.js` | `UI.Button` | primary/secondary/ghost/danger + loading/disabled/ripple |
  | `Input.js` | `UI.Input` | ช่องกรอกทุกฟอร์ม (ไอคอน/focus/error) |
  | `BottomNav.js` | `UI.BottomNav` | แถบเมนูล่าง 4 รายการ (customer/restaurant/rider/admin — เปลี่ยนเฉพาะ items) |
  | `Modal.js` | `UI.Modal` | กล่องโต้ตอบกลางจอ (`UI.openModal/closeModal`) |
  | `BottomSheet.js` | `UI.BottomSheet` | แผ่นเมนูเด้งจากด้านล่าง (action sheet) |
  | `Loading.js` | `UI.Loading` | spinner เต็มจอ/ในหน้า (login/โหลด Firebase/บันทึก) |
  | `StatusBadge.js` | `UI.StatusBadge` | ป้ายสถานะ เปิด/ปิด/ออนไลน์/ใหม่/เสร็จสิ้น |
  | `StatisticCard.js` | `UI.StatisticCard` | การ์ดสถิติ (ตัวเลขใหญ่ + ป้าย) |
  | `FoodCard.js` | `UI.FoodCard` | การ์ดอาหาร (รูปบน + ชื่อ + รายละเอียด + ราคา + ปุ่มเพิ่มตะกร้า) |
  | `RestaurantCard.js` | `UI.RestaurantCard` | การ์ดร้านค้า (รูป + ★ + เวลา + ระยะ + ปุ่มดูร้าน) |
  | `MenuCard.js` | `UI.MenuCard` | การ์ดเมนูกะทัดรัด (รูป + ชื่อ + ราคา + ปุ่ม ＋) |
  | `ui.js` | ตัวรวม | **ทุกหน้าโหลดไฟล์เดียวนี้** (`<script src="components/ui.js">`) component พร้อมใช้ + ripple อัตโนมัติ |
  | `CustomerBottomNav` | `UI.CustomerBottomNav` | แถบเมนูล่างฝั่งลูกค้า 6 เมนู (หน้าแรก/ร้านอาหาร/โปรโมชัน/ออเดอร์/ติดตามส่ง/บัญชี) + badge จำนวนออเดอร์ + click เปลี่ยนหน้า |

**ระบบรูปภาพจริง (แบบแอป Food Delivery):** ทุกการ์ดใช้ `UI.imgBlock` — มี `img`/`imageUrl` → แสดงรูปจริง · ไม่มีรูป → สร้าง **ภาพอาหาร/ร้านด้วย AI (Pollinations)** อัตโนมัติ (seed คงที่ต่อชื่อ = รูปเดิมทุกครั้ง) · โหลดไม่ได้/ไม่มีเน็ต → **fallback `images/no-*.png`** (ไม่แผลงเป็นกล่องดำ) — fallback: `no-food.png` / `no-store.png` / `no-avatar.png` (สร้างได้ใหม่ด้วย `node scripts/generate-fallbacks.js`)

**ใช้แล้วจริง:** `dashboard.html` / `rider.html` (AppHeader + UserCard + ActionCard + Button + BottomNav + StatisticCard + StatusBadge ครบ — โลโก้/avatar เป็นรูปจริง), `index.html` (FoodCard กริดเมนู + รูปชิปร้าน + แบนเนอร์ร้าน + ผลค้นหา), หน้า auth 3 หน้า (Input + Button) — เก็บ **id/class เดิมครบ** → JavaScript เดิมทำงานเหมือนเดิมทุกฟังก์ชัน

## 2.2) 📱 ติดตั้งเป็นแอปบนมือถือ (PWA — แยก 4 แอป)

ทุกหน้าติดตั้งลงหน้าจอมือถือได้แบบแอปจริง (เปิดเต็มจอ มีไอคอนของตัวเอง) — แยกเป็น **4 แอป** ตามบทบาท:

| แอป | หน้าเปิดแรก | สี/ไอคอน | วิธีติดตั้ง |
|---|---|---|---|
| **🍜 ZapNow** (ลูกค้า) | `index.html` | ส้ม `#FF7A1A` · กระเป๋า+รถ | เปิดเว็บสด → Chrome/Edge → เมนู ⋮ → **ติดตั้งแอป** (หรือ iOS Safari → แชร์ → **เพิ่มไปที่หน้าจอหลัก**) |
| **🏪 Sangkha Partner** (ร้านค้า) | `login.html` | ชมพู/แดง `#E11D48` · หน้าร้าน | เหมือนกัน — เข้าหน้า `login.html` |
| **🛵 Sangkha Rider** (ไรเดอร์) | `rider.html` | ม่วง `#7C3AED` · สกู๊ตเตอร์+หมวก | เหมือนกัน — เข้าหน้า `rider.html` |
| **🛡️ ZapNow Admin** (แอดมิน) | `admin.html` | ฟ้า `#2563EB` · โล่+ถูก | เหมือนกัน — เข้าหน้า `admin.html` |

แต่ละแอปมี **manifest ของตัวเอง** (`manifest-customer.json` / `manifest-partner.json` / `manifest-rider.json` / `manifest-admin.json`) + **ไอคอน 4 ขนาดของตัวเอง** (`icon-<แอป>-512/192/180/48.png`) + theme-color + apple-touch-icon (iOS) — แต่ละหน้ากลุ่ม (เช่น `dashboard.html` ใช้ manifest ร้านค้า, `finance.html` ใช้ manifest แอดมิน) |

**ข้อควรรู้:**
- ต้องเปิดผ่าน **HTTPS** (เว็บสด GitHub Pages มีให้แล้ว — `https://zapnowapp.github.io/ZapNow/...`) — เปิดที่ `127.0.0.1` ใช้ทดสอบได้ (ถือเป็น secure context)
- **Android** = ติดตั้งเต็มรูปแบบ (มีไอคอน + เปิดเต็มจอ) · **iOS** = ใช้ไอคอน + เปิดเต็มจอผ่าน apple-touch-icon/apple-mobile-web-app-capable (ไม่มีป้ายติดตั้งอัตโนมัติ ต้องกด "เพิ่มไปที่หน้าจอหลัก" เอง)
- ไอคอนเจนใหม่ได้เมื่ออยากแก้ดีไซน์: `node scripts/generate-app-icons.js`

## 3) วิธีดูทีละหน้า

### หน้า 1 — หน้าร้านอาหาร (ลูกค้า)

**URL:** `http://127.0.0.1:4173/`

**โครงสร้างหน้าเป็น Mobile App (6 แท็บ — แถบเมนูล่าง `UI.CustomerBottomNav`):** 🏠 **หน้าแรก** (**สไลด์โฆษณาบนสุดติดอยู่กับที่** — หมุนอัตโนมัติซิงก์กับแท็บร้านอาหาร (ลูกศร/จุด/⏱/นับถอยหลัง/คลิกไปหน้าโปรโมชันครบ) + เลื่อนลงไกล**ย่อเป็นแถบสไลด์บาง (ยังเห็นโฆษณาอยู่ตลอด — ไม่หาย): หดเหลือ 54px เหลือหัวข้อ + นับถอยหลัง + อีโมจิ/รูปสินค้าย่อ + ปุ่ม "ดู →" กระพริบ — สไลด์ยังหมุน/คลิกได้ตามปกติ แล้วขยายกลับเต็มเมื่อเลื่อนขึ้น** — **สไลด์หน้าแรกกรองเฉพาะหมวดที่ตรงร้านที่ลูกค้าติดตาม/ใกล้ตัว** (ตั้งหมวดได้ในฟอร์มโฆษณา admin — "ทุกหมวด" = โชว์ทุกหน้า / ติดตามร้านเบอร์เกอร์แล้วโฆษณาเบอร์เกอร์โผล่ทันที / แท็บร้านอาหารเห็นโฆษณาทั้งหมด — **ร้านตั้งหมวดโฆษณาของตัวเองได้ในหลังร้าน** (โปรไฟล์ → "หมวดโฆษณาร้าน" — เลือกหมวดที่ร้านขาย ไม่ต้องรอแอดมิน — สะท้อนลง Firestore เห็นข้ามเครื่อง / แอดมินแก้ให้ได้ใน panel แก้ไขข้อมูลร้าน)) แล้วตามด้วย สวัสดี + ชื่อสมาชิก + 📍 ส่งที่ + ค้นหา "ค้นหาร้านอาหาร หรือ เมนู" + 🔥 โปรโมชั่นเด็ด (Promotion Card — รูป/พื้นหลัง + ข้อความ + ปุ่มดูโปรโมชัน) + 🍜 ร้านอาหารใกล้คุณ (RestaurantCard — รูปจริง + ★ + ประเภท + ระยะทาง + เวลาส่ง + ปุ่มดูร้าน → สลับไปแท็บร้านอาหาร)) / 🍜 **ร้านอาหาร** (ระบบเดิมทั้งหมด: สไลด์โฆษณา + ช่องค้นหา + ชิปร้าน + หัวร้าน + **หมวดเมนูเฉพาะร้าน** — แท็บหมวด (แนะนำ/จานหลัก/เครื่องดื่ม/ของหวาน) แสดงเฉพาะหมวดที่ร้านนั้นมีเมนูจริง ร้านไหนไม่มีหมวดไหนปุ่มนั้นหายอัตโนมัติ (อัปเดตเมื่อสลับร้าน/เมนู Firestore เปลี่ยน) + เมนู + ตะกร้า) / 🔥 **โปรโมชัน** (รายการดีลแนวตั้งจากทุกแบนเนอร์ที่กำลังออกอากาศ — รูป/พื้นหลัง + ป้ายโฆษณา + ⏳ เวลาหมดเขต (ถ้าตั้ง endAt) + ปุ่ม CTA → คลิกเปิดหน้าโปรโมชันเต็ม `deal.html?id=...` + นับคลิกโฆษณา — อัปเดตสดเมื่อแอดมินแก้โฆษณา) / 📦 **ออเดอร์** (การ์ดออเดอร์: เลขที่/ร้าน/รายการ/ราคา/เวลา/สถานะ 🟡🟠🔵🛵🟢 + ปุ่มติดตาม/สั่งซ้ำ + badge จำนวนออเดอร์ค้างบนแถบเมนู) / 🛵 **ติดตามส่ง** (ขั้นสถานะ + ไรเดอร์ (ชื่อ/เบอร์/ETA) + แผนที่ Leaflet ตำแหน่งไรเดอร์สด + ปุ่มเปิด Google Maps) / 👤 **บัญชี** (รูปโปรไฟล์/ชื่อ/เบอร์ + เมนู: แก้ไขข้อมูล/ที่อยู่จัดส่ง/ร้านโปรด/คูปอง/ประวัติออเดอร์/คะแนนสะสม/ตั้งค่า/ออกจากระบบ)

บนหน้านี้มีทั้งหมด (เรียงตามแท็บ):
1. **แบนเนอร์โฆษณา (สไลด์หมุน)** — โฆษณาหมุนสลับอัตโนมัติ**วนรอบตลอดเวลา** (0→1→2→3→0...) แบบ carousel เลื่อนซ้าย/ขวา (เข้า-ออกตามทิศทางที่กด): ลูกศร ‹ › เลื่อนเองได้, จุดบอกตำแหน่ง, ปัดนิ้วซ้าย/ขวาบนมือถือ, นับถอยหลัง + แถบเวลา, หยุดหมุนเมื่อเมาส์ชี้, **แถบความคืบหน้าของแต่ละสไลด์** (เวลาเหลือก่อนหมุนไปสไลด์ถัดไป), และปุ่ม **⏱ ปรับความเร็วหมุน** (3/5/8/10 วิ — จำค่าไว้ใน localStorage `sangkha-ad-speed`) — (สไลด์แรกยังรองรับคลิปวิดีโอ — **แอดมินตั้งวิดีโอได้จากฟอร์มโฆษณาในหน้า admin**: วาง**ลิงก์เต็ม https://.../คลิป.mp4** (เล่นจากเว็บตรง ๆ ไม่ต้องวางไฟล์) หรือใส่**ชื่อไฟล์** เช่น `promo-burger` (วาง `promo-burger.mp4`/`.webm` ในโฟลเดอร์ — ระบบเติมนามสกุลให้อัตโนมัติ) — คลิปเล่นวน (loop) + มี **ป้าย "🎬 คลิป" และปุ่มปิดเสียง 🔊/🔇** (คลิปเริ่มต้นเป็นแบบปิดเสียงเพื่อให้ autoplay ผ่าน — กดปุ่มเสียงไม่เด้งไปหน้าโปรโมชัน) — **ถ้าคลิปโหลดไม่ได้/ลิงก์เสีย ระบบซ่อนวิดีโอ + ป้ายคลิป/ปุ่มเสียงอัตโนมัติ แล้วใช้พื้นหลังไล่สีแทน (กันสไลด์ดำ/ขาว — เช็คด้วย readyState ครอบคลุมมือถือที่ networkState รายงานไม่ตรง)** — **ปัดมือถือแล้วไม่เด้งไปหน้าโปรโมชัน** (กัน click จำลองที่เบราว์เซอร์ยิงตามหลังปัด 400ms แต่แตะปกติยังเปิด) — **สไลด์ที่ไม่มีรูปแบรนด์ (หรือมีแค่พื้นหลัง AI) แสดงอีโมจิแทนเสมอ ไม่มีช่องว่าง** — **แอดมินตรวจคลิปก่อนบันทึก**: พิมพ์/วางลิงก์แล้วระบบเช็คอัตโนมัติ (โหลดไม่ได้ = แจ้งเตือนแดงทันที) และตอนกดบันทึกถ้าคลิปใช้ไม่ได้จะ**ไม่บันทึก** + เตือนให้แก้หรือเว้นว่าง (แทนการเงียบ ๆ ซ่อนที่หน้าร้าน) — หมุนวนยังทำงานแม้เปิดโหมดลดการเคลื่อนไหว (แค่ไม่เลื่อนสไลด์))
2. **🔍 ค้นหาร้าน/เมนูข้ามร้าน** (ช่องค้นหาตรงใต้แบนเนอร์) — พิมพ์ชื่อร้าน/ประเภท/เมนู เช่น "พิซซ่า" → ค้นข้ามทุกร้าน ผลแบ่ง 2 กลุ่ม: **ร้านค้า** (คลิก = สลับไปร้านนั้น) และ **เมนู** (คลิกการ์ด = ไปร้านนั้น / กด "เพิ่มลงตะกร้า" = สั่งได้เลยโดยสลับร้านให้อัตโนมัติ) — ล้างด้วยปุ่ม ✕ หรือ Esc — **หัวติดอยู่กับที่**: สไลด์โฆษณา + ช่องค้นหา **ติดอยู่บนสุดตลอดเวลา** กดเลื่อนดูเมนูก็ยังเห็น (ห่อใน `.sticky-head`) — **หดอัตโนมัติเมื่อเลื่อนลงไกล** (> 140px): สไลด์ใหญ่ย่อเป็น**แถบโฆษณาบาง** (แสดงหัวข้อโฆษณาที่กำลังแสดงอยู่ + แตะ = เปิดหน้าโปรโมชัน + นับคลิก) เหลือช่องค้นหาเต็ม — เลื่อนขึ้นใกล้บนสุด = ขยายกลับเป็นสไลด์ใหญ่
3. **แถบเลือกร้านค้า** — คลิกเพื่อสลับไปร้านอื่น (ครัวสังขา / พิซซ่าคิง / ก๋วยเตี๋ยวป้าแดง / คาเฟ่บัตเตอร์) ข้อมูลร้านและเมนูจะเปลี่ยนตาม — **ลูกค้าสลับการเรียงชิปร้านได้เอง**: ปุ่ม **"📍 ใกล้สุด"** (เรียงตามระยะทางจริง Haversine เมื่อมีตำแหน่ง ถ้าไม่มีใช้ระยะที่ร้านกรอก) / **"⭐ คะแนนสูงสุด"** (เรียงตามคะแนนรีวิว) — จำตัวเลือกไว้ใน `sangkha-store-sort` — ค่าเริ่มต้น: มีตำแหน่ง → ใกล้สุด / ไม่มีตำแหน่ง → ลำดับเดิม
4. **ข้อมูลร้าน** — ชื่อ, ประเภทอาหาร, คะแนน ★, เวลาเปิด-ปิด, ระยะทาง, แท็กส่งฟรี + **🟢 เปิดอยู่/🔴 ปิดอยู่ ตามเวลาจริง** (เทียบเวลาเปิด-ปิดของร้าน — รองรับร้านข้ามเที่ยงคืน — อัปเดตทุก 30 วิ) + ปุ่ม **🔖 ติดตามร้าน** (กดติดตาม/เลิกได้ — สถานะแยกร้านและจำไว้) และป้าย **"ใหม่"** บนร้านที่เพิ่งสมัคร — **ร้านที่ปิดอยู่**: ชิปร้านในแถบร้านค้าจางลง + ป้าย "🔴 ปิดอยู่" + กด **"＋ เพิ่มลงตะกร้า"** ไม่ได้ (แจ้ง "ร้านปิดอยู่") + ปุ่ม **"สั่งซื้อ"** ในตะกร้าเป็น **"🔴 ร้านปิดอยู่"** (กดไม่ได้) + เช็คซ้ำตอนยืนยันสั่งซื้อ (กันสั่งช่วงปิดร้านได้จริง) — ร้านจะกลับมาสั่งได้เองเมื่อถึงเวลาเปิด — **🔴 ปิดชั่วคราว (ร้านตั้งเอง)**: เหมือนร้านปิดทุกอย่าง แต่ป้ายเป็น "🔴 ปิดชั่วคราว" (ชิปร้าน/หัวร้าน/ปุ่มสั่ง) + ถ้าร้านใส่เหตุผลไว้ ลูกค้าเห็นเป็น tooltip — ร้านตั้ง/ยกเลิกได้จากหน้า admin/dashboard โดยไม่ต้องแก้วลาเปิด-ปิด — **🔴 ปิดอัตโนมัติ (ออเดอร์ค้างถึงเกณฑ์)**: ป้าย "🔴 ปิดอัตโนมัติ (ค้าง N ใบ)" + tooltip บอกเกณฑ์ — ระบบเปิดรับเองเมื่อเคลียร์ออเดอร์ — **ระยะทางแสดงตามจริง (Haversine จากพิกัดร้าน ↔ พิกัดลูกค้า)** เมื่อมีตำแหน่ง (กดปุ่ม **"📍 ใช้ตำแหน่งของฉัน"** — เม็ดเล็กทับมุมล่างซ้ายของภาพหน้าร้าน พื้นหลังเข้มโปร่งแสงอ่านชัดบนรูปทุกแบบ — หรือปักหมุด GPS ตอนสั่งซื้อ — จำไว้ใน `sangkha-customer-gps`) — ระยะทางจริงปรากฏที่หัวร้าน (มีป้าย GPS), ชิปร้าน และผลค้นหา ถ้าไม่มีตำแหน่งใช้ระยะทางที่ร้านกรอก
5. **หมวดหมู่เมนู** — แนะนำ / จานหลัก / เครื่องดื่ม / ของหวาน
6. **รายการเมนู** — รูปอาหาร, ราคา, ปุ่ม "เพิ่มลงตะกร้า" (มีโฆษณาแทรกระหว่างเมนู) — เหนือรายการเมนูมีแถว **"🔥 ดีลเด็ด"**: การ์ดโปรโมชันเลื่อนแนวนอน (สีของโฆษณา + อีโมจิ + ปุ่ม CTA) — **คลิกการ์ด = เปิดป๊อปอัปดีลเด็ดกลางจอ** (ไม่ต้องออกจากหน้า — แถบเมนูล่างไม่หาย): แบนเนอร์ (รูป/วิดีโอ/Ken Burns + ป้ายโฆษณา + ⏳ นับถอยหลังสด) + 🎟️ ชิปคูปอง + เงื่อนไข (คลิกเปิด-ปิด) + ปุ่ม **รับคูปอง** (เก็บเข้าบัญชีใช้ตอนสั่งซื้อได้เลย) + ลิงก์ "ดูหน้านี้แบบเต็ม" → `deal.html?id=...` — ปิดด้วย ✕ / แตะพื้นหลัง / Esc + นับคลิกเข้าสถิติ (โฆษณาแทรกในเมนูก็เปิดป๊อปอัปเดียวกัน) / กด "ดูทั้งหมด →" ไปหน้า `/deals.html`
7. **ตะกร้า (ป๊อปอัปกลางจอ)** — ปุ่ม 🛒 ลอยมุมขวาล่าง (ทุกจอ — badge จำนวนสินค้า) → กดเปิดเป็น **ป๊อปอัปกลางจอ** (เหมือนฟอร์มสั่งซื้อ — มุม 20px + เงา + ปุ่ม ✕ ปิด / แตะพื้นหลังปิด) — เพิ่ม/ลดจำนวน, รวมยอด, ค่าจัดส่ง (ฟรีเมื่อถึงขั้นต่ำ), **💸 ค่าแพลตฟอร์ม (X%)** — ปุ่มสั่งซื้อ — **ราคารวม = ค่าอาหารจริง + ค่าจัดส่งตามระยะทาง + ค่าแพลตฟอร์ม** — **ค่าจัดส่งคำนวณจากระยะทางถนนจริง (OSRM) ให้ตรงกับเส้นทางบนแผนที่** — เริ่มจากระยะ Haversine ทันที แล้วเมื่อ OSRM โหลดเสร็จ (แคชต่อคู่พิกัด) ค่าส่ง/ระยะทางบนตะกร้า+ฟอร์มสั่งซื้อจะ**อัปเดตเป็นระยะถนนจริง** (เช่น เส้นตรง 2.4 กม. → ถนนจริง 3.7 กม. → ค่าส่ง 25+5×3.7 = ฿44) — ไม่มีพิกัดครบใช้ distanceKm ที่ร้านกรอก (ค่าส่ง = ค่าเริ่มต้น + ต่อกม. × ระยะทาง ตั้งอัตราได้ที่ admin) — ในฟอร์มสั่งซื้อมีปุ่ม **"📍 ใช้ตำแหน่งปัจจุบันของฉัน (GPS)"**: กดปุ่มเดียว ระบบขอตำแหน่ง GPS จากเบราว์เซอร์ → แปลงเป็นที่อยู่จริง (OpenStreetMap Nominatim ไม่ต้องใช้คีย์ ถ้าแปลงไม่ได้ใช้พิกัดแทน) → เติมช่องที่อยู่ให้อัตโนมัติ + **ค่าส่ง/คูปองคำนวณใหม่ตามระยะทางถนนจริง** + เก็บพิกัด + ระยะทางที่ใช้ติดออเดอร์ (dashboard/ไรเดอร์เห็น "📌 พิกัด GPS" และระยะทางจริง) — **ชิปร้าน/หัวร้าน/ผลค้นหาแสดงระยะทางถนนจริงของทุกร้าน** (โหลด OSRM พื้นหลังเมื่อใช้ตำแหน่ง — แต่ละร้านโหลดเสร็จวาดใหม่ทันที + เรียง "ใกล้สุด" ตามระยะถนนจริงด้วย — ร้านที่ยังโหลดไม่เสร็จ/ไม่มีพิกัดใช้ Haversine หรือ distanceKm ที่กรอก) — อนุญาตตำแหน่งแล้วกดปุ่มได้ทันที
8. **แถบติดตามสถานะออเดอร์ (สด)** — หลังสั่งซื้อเสร็จ จะมีแถบแสดงสถานะแบบเรียลไทม์: 📥 ได้รับออเดอร์ → 👨‍🍳 กำลังเตรียม → 🛵 กำลังจัดส่ง → ✅ ถึงมือแล้ว (ขั้นที่ถึงอยู่กะพริบ) — **อัปเดตอัตโนมัติ** เมื่อร้านค้าขยับสถานะที่ dashboard (เปิดคนละแท็บก็อัปเดตให้) — ปิดได้ด้วยปุ่ม ✕ หรือปุ่ม "เรียบร้อย ✓" เมื่อเสร็จสิ้น และเมื่อออเดอร์เสร็จสิ้นจะมีช่อง **✨ ให้คะแนน + รีวิว** (เลือกดาว 1–5 + เขียนรีวิวสั้น ๆ) — ส่งแล้ว**คะแนนร้านบนหน้าร้านอัปเดตตามจริง**
9. **🗺️ แผนที่จริงตำแหน่งไรเดอร์ (Leaflet + OSM + เส้นทางถนน OSRM)** — เมื่อไรเดอร์รับงาน (กำลังจัดส่ง) แถบติดตามจะแสดง**แผนที่จริง** (Leaflet + OpenStreetMap — ฟรี ไม่ต้องใช้คีย์): แสดง 🏪 ร้าน → **เส้นทางวิ่งตามถนนจริง (OSRM — ฟรี ไม่ต้องใช้คีย์ ใช้เส้นตรงแทนถ้าโหลดไม่ได้)** → 🏠 บ้านคุณ + ไรเดอร์ 🛵 ขยับตามเวลาจริง **ทุก 2 วิ** พร้อม ETA (คำนวณจาก**ระยะทางถนนจริง** ÷ 45 กม./ชม.) — **🏠 บ้านคุณวางตามพิกัด GPS ที่ปักหมุดตอนสั่งซื้อ และ 🏪 ร้านวางตามพิกัดที่ร้านใส่ตอนสมัคร (ถ้ามี)** — ไม่มีพิกัด = ค่าเริ่มต้น + jitter คงที่ต่อร้าน/ออเดอร์ (กรุงเทพฯ)
10. **📍 ไรเดอร์กดอัปเดตตำแหน่งจริง** (หน้า rider → งาน "กำลังส่งของฉัน"): ไรเดอร์กดปุ่มตามขั้น **"🏪 ถึงร้านแล้ว" → "🛵 เริ่มไปส่ง" → "✅ ส่งถึงแล้ว"** (การ์ดมีตัวบอก "📍 ระยะ 1/3 … 2/3 … 3/3") — ลูกค้าที่หน้าร้านเห็น**ข้อความ/ตำแหน่ง/ETA บนแผนที่เปลี่ยนตามทันที**: "กำลังไปรับอาหารที่ร้าน" (ไรเดอร์อยู่ที่ร้าน) → "ถึงร้านแล้ว กำลังรับอาหาร" → "กำลังนำส่ง" (ไรเดอร์วิ่งจากร้านถึงบ้าน + นับ ETA) — เริ่มนับเวลาเดินทางตอนกด "เริ่มไปส่ง"
11. **🤖 จัดงานให้ไรเดอร์อัตโนมัติ** — ร้านกด "พร้อมส่งแล้ว" ระบบ**เลือกไรเดอร์ว่าง/ใกล้สุด** (จำลอง: รอว่างนานสุด → งานวันนี้น้อยสุด → ต้องผ่าน whitelist ของร้าน และไม่ว่าง = มีงานกำลังส่งอยู่) ส่งงานให้ทันที ไรเดอร์คนนั้นเห็น toast "🤖 ระบบจัดงาน #N ให้คุณ" + งานขึ้นแท็บ "กำลังส่งของฉัน" — ถ้าไม่มีใครว่าง งานลง pool ให้กดรับเอง
9. **🧾 ประวัติออเดอร์** (แถบเมนูล่าง: 📦 **ออเดอร์** + 👤 **บัญชี** → "ประวัติออเดอร์" — ปุ่มเดิมข้างหัวข้อ "ร้านค้า" ถูกลบแล้วเพราะซ้ำกับแถบเมนูล่าง) — เปิดโมดัลดูออเดอร์ทั้งหมดที่เคยสั่ง (ทุกคนทุกสถานะ: ใหม่/กำลังเตรียม/กำลังจัดส่ง/เสร็จสิ้น/ยกเลิก) พร้อมวันที่-เวลา, รายการอาหาร, ยอดรวม และปุ่ม **"🔄 สั่งซ้ำ"** — คลิกเดียว: สลับไปร้านนั้น (ถ้ายังไม่ใช่) + เติมสินค้าเดิมลงตะกร้าเลย (เมนูที่ถูกลบจากร้านจะข้ามและแจ้งให้ทราบ)

1. **เข้าสู่ระบบไรเดอร์ (แยกหน้าต่อคน — เห็นเฉพาะของตัวเอง)**: หน้าเปิดมา = panel **"เข้าสู่ระบบ / ลงทะเบียนไรเดอร์"** (ชื่อ + เบอร์โทร) — **ไรเดอร์ได้หลายคน** แต่แต่ละคนต้องล็อกอินด้วย **ชื่อ + เบอร์ของตัวเอง** (ค้นจากทะเบียน ไม่มี dropdown รายชื่อคนอื่น — ไรเดอร์คนอื่นมองไม่เห็นหน้านี้) → ปุ่ม **"🚪 เข้าสู่ระบบ"** / ยังไม่เคยลงทะเบียน → **"＋ ลงทะเบียน"** (สร้าง + ล็อกอินให้เลย) — หลังล็อกอินแถบเปลี่ยนเป็น **"กำลังทำงานเป็น {ชื่อ} · {เบอร์}" + ปุ่ม "🚪 ออกจากระบบ"** — งาน/รายได้/กระเป๋าเงิน/ประวัติ = ของคนที่ล็อกอินเท่านั้น (สลับคนต้องออกก่อนแล้วล็อกอินใหม่)
1.5 **👤 โปรไฟล์ของฉัน** (การ์ดใต้สถิติ) — เห็นข้อมูลตัวเอง: **ชื่อ** (กด "✏️ แก้ไข" แล้วเปลี่ยนได้ — **กันชื่อซ้ำ**กับไรเดอร์คนอื่น) / **เบอร์โทร** (กด "✏️ แก้ไข" แล้วบันทึกเบอร์ใหม่ได้ — เบอร์ซ้ำกับไรเดอร์คนอื่นจะถูกกัน) / **อีเมล (รับสลิป)** (กด "✏️ แก้ไข" แล้วบันทึกอีเมล — ใช้รับสลิปรายเดือน) / **วันสมัคร** / **ส่งแล้วทั้งหมด** (จำนวนงาน) / **รายได้รวม** (รวมค่าส่งทุกงานที่ส่งสำเร็จ — อัปเดตสด) — แก้ชื่อ/เบอร์/อีเมลแล้วอัปเดตทะเบียน + เซสชันให้ตรงทันที
2. **สถิติ** — รอรับงาน / กำลังส่งของฉัน / ส่งแล้ววันนี้ / รายได้วันนี้ (รวมค่าจัดส่งที่ส่งสำเร็จ)
3. **แท็บงาน** 3 แบบ:
   - **🛵 รอรับงาน** — ออเดอร์ที่ร้านกด "พร้อมส่งแล้ว" (อาหารเสร็จรอรับ): แสดงเส้นทาง ร้าน → ลูกค้า, รายการ, ยอดรวม → กด **"🛵 รับงานนี้"** = ออเดอร์เปลี่ยนเป็น กำลังจัดส่ง + ระบุชื่อไรเดอร์
   - **📦 กำลังส่งของฉัน** — ออเดอร์ที่รับแล้ว: ชื่อ/เบอร์/ที่อยู่/หมายเหตุลูกค้าเต็ม + ปุ่ม **"📞 โทรหาลูกค้า"** และ **"🗺️ เปิดแผนที่"** — ถ้าลูกค้าปักหมุด GPS (จากปุ่มในฟอร์มสั่งซื้อ) ปุ่มจะเป็น **"🗺️ เปิดแผนที่ (GPS)"** นำทางไป `maps.google.com/?q=lat,lng` (พิกัดที่ปักหมุด) ถ้าไม่มีใช้ที่อยู่ที่พิมพ์แทน → กด **"✅ ส่งถึงแล้ว"** = ออเดอร์เสร็จสิ้น (ลูกค้าที่หน้าร้านเห็นสถานะเปลี่ยนทันที) หรือ **"↩️ คืนงาน"** = ปล่อยกลับไปให้คนอื่นรับ
   - **🗺️ แผนที่นำทางจริง (Leaflet + OpenStreetMap + เส้นทางถนน OSRM)** — ทุกการ์ด (รอรับงาน/กำลังส่ง) มีปุ่มเปิดแผนที่: โมดัลแสดง**แผนที่จริง** (Leaflet + OSM — ฟรี ไม่ต้องใช้คีย์) พร้อม**เส้นทางวิ่งตามถนนจริง (OSRM — ฟรี ไม่ต้องใช้คีย์ ใช้เส้นตรงแทนถ้าโหลดไม่ได้)** + จุดหมาย — **"🏪 ไปรับของที่ร้าน"**: จุดเริ่ม = ไรเดอร์ (สุ่มคนละจุด ห่างจากร้านเล็กน้อย) → ร้าน — **"🏠 ไปส่งลูกค้า"**: ร้าน → บ้านลูกค้า — **🏠 บ้านลูกค้าวางตามพิกัด GPS ที่ปักหมุดจริง + 🏪 ร้านวางตามพิกัดที่สมัคร (ถ้ามี)** (โชว์ lat, lng ใต้ป้ายบ้าน) — สลับ 2 แผนที่ได้ในโมดัล + ETA + อัปเดตทุก 2 วิ — **⏱️ ETA คำนวณจากระยะทางถนนจริง (OSRM) ÷ ความเร็ว 45 กม./ชม.** (เส้นทางยาว = ใช้เวลานาน ไรเดอร์ขยับความเร็วสม่ำเสมอ — หัวการ์ดโชว์แยกสองขา: "ไปรับ ~2 นาที (~0.2 กม.) · ไปส่ง ~7 นาที (~5.1 กม.) · รวม ~9 นาที" — ระยะทางถนนจริงยาวกว่าเส้นตรงเสมอ และโมดัลโชว์ "ถึงในอีก X นาที · เส้นทาง ~X.X กม.")
   - **✅ ส่งแล้ว** — **ประวัติงานที่ส่งสำเร็จทั้งหมด (ไม่จำกัดแค่วันนี้)** + **กรองตามเดือน** (dropdown "🗓️ ทุกเดือน" หรือเลือกเดือน — ตัวเลือกโชว์จำนวนงาน + รายได้ของเดือนนั้น) + **สรุปรายได้** แถบด้านบน: "📊 ทั้งหมด X งาน · รายได้รวม ฿Y" (หรือของเดือนที่เลือก) + รายได้แต่ละงาน + ลบออกได้ — การ์ดสถิติบนสุด "ส่งแล้ววันนี้ / รายได้วันนี้" ยังเป็นของวันนี้ตามเดิม
4. **รับงานพร้อมกันแบบเรียลไทม์ + ห้ามรับซ้ำ**: ร้านกด "พร้อมส่งแล้ว" เมื่อไหร่ งานเด้งขึ้นให้ไรเดอร์ทุกคนทันที (เสียง + toast + Notification + ชื่อแท็บ) — ไรเดอร์ 2 คนกดรับงานเดียวกันพร้อมกัน **คนแรกที่กดได้งาน** อีกคนโดนแจ้ง **"⏱️ งานนี้ {ชื่อ} รับไปก่อนแล้ว"** และงานหายจากรายการรอรับทันที (อัปเดตทุก 3 วิ + ข้ามแท็บ)
5. **🏠 ไรเดอร์ประจำร้าน (whitelist)**: ร้านตั้งได้ในหน้า admin (ส่วน "🛵 ไรเดอร์ประจำร้าน" ใต้แถบเลือกร้าน) — เลือกไรเดอร์ให้ร้านตัวเอง งานจากร้านนั้นจะ**ขึ้นเฉพาะไรเดอร์ในกลุ่ม** (การ์ดติดป้าย "🏠 ประจำร้าน") — ไม่เลือกใคร = ไรเดอร์ทุกคนเห็นงานของร้านนั้น (ร้านต่าง ๆ ตั้งคนละกลุ่มได้)
6. **💰 กระเป๋าเงินไรเดอร์** (ใต้สถิติ): **รายได้สะสม** = ค่าจัดส่งของทุกงานที่ส่งเสร็จ (ทุกวัน ไม่ใช่แค่วันนี้) — แสดง **เบิกไปแล้ว** และ **เบิกได้ (คงเหลือ)** — กรอกจำนวน → กด **"💸 เบิกถอน"** (กันเบิกเกินยอด) — มี **🧾 ประวัติการเบิก** (วัน-เวลา + จำนวน + ลบได้) เก็บใน `sangkha-rider-withdrawals` — งานที่ถูกลบออกจากประวัติ ยอดสะสมลดตาม
6.5 **📧 สลิปรายเดือนทางอีเมล** (ปุ่ม "📧 ส่งสลิปรายเดือน" ในแถบกรองเดือนของแท็บ "✅ ส่งแล้ว") — เปิดโมดัลสลิป: **สรุปงาน** (จำนวนงาน) + **รายได้รวม** (ค่าจัดส่ง) + **ภาษีหัก ณ ที่จ่าย** (อัตราตามที่ตั้งในหน้า admin — ค่าเริ่มต้น 3% มาตรา 40(8) — คำนวณต่อใบตามร้าน + เวลาส่งเสร็จของงานนั้น — อัตราเดียวกันทั้งงวดแสดง "(3%)" ต่างกันแสดง "(อัตราแปรผัน)") + **ยอดสุทธิรับ** + **🏪 สรุปภาษีรายร้าน** (แยกกลุ่มต่อร้าน: ชื่อร้าน / จำนวนงาน / รายได้ / อัตราที่ใช้ / ยอดหักรวมของร้านนั้น — เห็นชัดว่าร้านไหนถูกหักเท่าไร ก่อนยอดรวม) + **ตารางรายการงาน** (วัน-เวลา / #ออเดอร์ / ร้าน / ค่าส่ง / **หัก ณ ที่จ่าย** — โชว์ยอด + อัตราต่อใบ) — กรอกอีเมล → **"📧 ส่งอีเมล"** เปิดโปรแกรมอีเมล (mailto) พร้อมข้อความสลิปเต็ม (หัวเรื่อง + เนื้อหา — มีส่วนสรุปภาษีรายร้านด้วย) → อีเมลถูกจำไว้ (โปรไฟล์) + บันทึกประวัติการส่ง ("📨 ส่งล่าสุด … ไปยัง …") เก็บใน `sangkha-rider-slips` — หรือกด **"📋 คัดลอก"** วางลงอีเมล/แชทเอง — สลิปตามเดือนที่กรองอยู่ (เลือก "ทุกเดือน" = บันทึกยอดรวมทุกช่วงเวลา)
7. **🔔 แจ้งเตือนงานใหม่แบบ push** (Service Worker `sw.js`): ทุกหน้าที่เปิดอยู่ในเบราว์เซอร์ (หน้าร้าน/admin/dashboard/ดีล) จะส่งงาน "พร้อมส่ง" ใหม่ให้ SW → SW แสดง **Notification ของระบบ** + **badge จำนวนงานบนไอคอนแอป** (Chromium) + **เสียงติ๊ง** (ปลดล็อกหลังแตะหน้าครั้งแรก) — แจ้ง**แม้ไม่ได้อยู่ที่หน้า rider** (อยู่แท็บอื่นก็ได้) — คลิกแจ้งเตือน = เปิด/โฟกัส Rider Dashboard — 1 งานแจ้ง 1 ครั้ง (กันซ้ำด้วย tag) — หมายเหตุ: ข้อมูลอยู่ใน localStorage (ไม่มีเซิร์ฟเวอร์ push) จึงต้องมีหน้าใดหน้าหนึ่งเปิดอยู่
8. **🛵 ป๊อปอัปลอยงานใหม่ (มุมบน)** — แม้ไม่ได้อยู่ที่แท็บ "งาน" (อยู่หน้าหลัก/รายได้/โปรไฟล์) เมื่อมีงาน "พร้อมส่ง" ใหม่จะขึ้นการ์ดลอยมุมบน (ขอบม่วง) แสดงร้าน/จำนวนรายการ/ยอดรวม/**💸 ค่าจัดส่งที่จะได้** + รายการอาหาร 3 รายการแรก + ปุ่ม **"🗺️ เปิดแผนที่"** (เปิดโมดัลแผนที่นำทางเดิม — ดูเส้นทาง/ระยะ/ETA ก่อนตัดสินใจ ไม่รับงาน) + ปุ่ม **"🛵 รับงานนี้"** (เรียก `assignRider` ฟังก์ชันเดิม — กันรับซ้ำ: โดนรับไปก่อน = แจ้งชื่อคนที่รับแล้ว) — แตะที่การ์ด = ไปแท็บงาน · ปิดอัตโนมัติหลัง 15 วิ · ซ้อนได้สูงสุด 3 ใบ · จำงานที่เห็นแล้ว (`sangkha-rider-ui-seen-jobs`) กันแจ้งซ้ำข้ามหน้าโหลด · เสียงติ๊งรอบแรกเมื่อเปิดหน้ามาเจองานค้าง

**วิธีลองสลิป:** ลงทะเบียนไรเดอร์ → แท็บ "✅ ส่งแล้ว" (ต้องมีงานส่งเสร็จ อย่างน้อย 1 ใบ) → กด **"📧 ส่งสลิปรายเดือน"** → โมดัลโชว์สรุปงาน + รายได้ + ภาษีหัก ณ ที่จ่าย 3% + ยอดสุทธิ → กรอกอีเมล → กด **"📧 ส่งอีเมล"** = เปิดโปรแกรมอีเมลพร้อมสลิป (หรือ **"📋 คัดลอก"** วางเอง)

**วิธีลองหลายไรเดอร์:** เปิด `rider.html` 2 แท็บ → แท็บ ก ลงทะเบียน "ไรเดอร์เปี๊ยก" → แท็บ ข ลงทะเบียน "ไรเดอร์จ๋า" (dropdown สลับคนได้) → ร้านกดพร้อมส่ง 1 งาน → ทั้ง 2 แท็บเห็นงาน → กดรับพร้อมกัน → คนที่ชนะได้งาน อีกคนเห็น "งานนี้ … รับไปก่อนแล้ว"

**วิธีลองครบวงจร:** เปิด 3 หน้าคนละแท็บ: หน้าร้าน (`/`) → สั่งซื้อ → dashboard (`/dashboard.html`) → รับออเดอร์ + พร้อมส่งแล้ว → rider (`/rider.html`) → ตั้งชื่อไรเดอร์ → รับงาน → ส่งถึงแล้ว → กลับมาหน้าร้าน เห็นแถบติดตามเป็น "ถึงมือแล้ว 🎉"

   - **🗑️ ลบ** → ยืนยันแล้วลบออกจากเมนู
   - **บทบาทต่างกัน**: **แอดมิน** → บันทึก/ลบใช้ทันที (ขึ้นหน้าร้านเลย) / **ร้านค้า** → บันทึก/ลบ **เข้าคิวรออนุมัติ** (`sangkha-pending-menu`) — เมนูยังไม่เปลี่ยนจนกว่าแอดมินอนุมัติ — สินค้าที่มีคำขอค้างอยู่ติดป้าย **⏳** บนการ์ด — **คิวรออนุมัติซิงก์ Firestore ด้วย** (`menuPending/queue` — สะท้อนทุกครั้งที่มีการเพิ่ม/ลบ + ดึงตอนเปิดหน้า + ฟังสด) — ร้านส่งขอจากมือถือ → แอดมินที่คอม/เครื่องอื่นเห็นทันที (มี **badge จำนวนรออนุมัติบนการ์ด "เมนู"** ในแดชบอร์ดแอดมิน — เห็นทันทีไม่ต้องเข้าหมวด)
3.5 **🕐 เมนูรออนุมัติ** (panel ใต้แถบเลือกร้าน — เฉพาะแอดมิน) — รายการที่ร้านค้าส่งขอเพิ่ม/แก้ไข/ลบ: ชื่อร้าน + การกระทำ + ชื่อสินค้า/ราคา/หมวดหมู่ + เวลาที่ส่ง → กด **"✅ อนุมัติ"** = นำไปใช้กับเมนูจริง (ขึ้นหน้าร้านทันที) / **"ปฏิเสธ"** = ไม่ใช้ — อัปเดตสดข้ามแท็บ (ร้านส่งในแท็บอื่น แอดมินเห็นทันที)
3.6 **🔑 รีเซ็ต PIN ร้าน** (panel ใต้เมนูรออนุมัติ — เฉพาะแอดมิน) — เลือกร้าน + ตั้ง **PIN ใหม่** → **"💾 บันทึก PIN ใหม่"** (อย่างน้อย 4 ตัว) — ใช้เมื่อร้านลืมรหัส (badge แสดง PIN ปัจจุบันของร้านนั้น) — PIN ใหม่มีผลทันที ร้านต้องล็อกอินด้วย PIN ใหม่ (ร้านที่ยังไม่เคยรีเซ็ต ใช้ PIN ตอนสมัคร/ค่าเริ่มต้น 1234)
3.7 **🏪 แก้ไขข้อมูลร้าน** (panel ใต้รีเซ็ต PIN — เฉพาะแอดมิน) — เลือกร้าน + แก้**ครบทุกข้อมูลสมัคร**: **ชื่อร้าน / ประเภทอาหาร / โลโก้ (อีโมจิ + สีพื้นหลัง) / เวลาเปิด-ปิด / ที่อยู่ / ระยะทาง (กม.) / ค่าส่ง / ส่งฟรีขั้นต่ำ / เวลาจัดส่ง / พิกัด Lat-Lng** → **"💾 บันทึก"** (กันชื่อ/ประเภทว่าง) — ร้านสมัครผิดแล้วแก้เองไม่ได้ แอดมินแก้ให้ (เก็บใน `sangkha-store-edits` — ส่งผลทั้งหน้าร้าน/หลังร้านทันที — ช่องว่าง = ใช้ข้อมูลเดิม) — **"คืนค่าเดิม"** = กลับไปใช้ข้อมูลที่สมัคร/ตั้งต้นทั้งหมด — ปุ่ม **"👁️ ดูตัวอย่างหน้าร้าน"** (มุมขวาบน) เปิดพรีวิวจำลอง: แบนเนอร์ (โลโก้+สี+ชื่อ+คะแนน + **🟢 เปิดอยู่/🔴 ปิดอยู่ ตามเวลาปัจจุบันเทียบเวลาเปิด-ปิดที่กรอก** — รองรับร้านข้ามเที่ยงคืน + รีเฟรชทุก 30 วิ ขณะเปิดโมดัล) + รายละเอียด + **🍽️ เมนูตัวอย่าง 3 รายการแรก** ของร้านนั้น (แสดงเฉพาะรายการที่อนุมัติแล้ว — อัปเดตสดตามค่าที่พิมพ์/เลือก ยังไม่บันทึก) — ปุ่ม **"🗑️ ลบร้านสมัคร"** (แดง มุมล่าง panel — เฉพาะร้านที่สมัคร ร้านพื้นฐานลบไม่ได้): ยืนยัน → **ลบออกจาก Firestore + เครื่องทั้งหมดไม่เหลือ residue** (ทะเบียนร้าน/เมนู/บัญชีผู้ใช้/พิกัด/ค่าส่ง/ค่าธรรมเนียม/ไรเดอร์ประจำร้าน/ปิดชั่วคราว/การติดตาม/เมนูรออนุมัติ) — **ประวัติออเดอร์/การเงินเดิมของแพลตฟอร์มคงไว้** (อ้างอิงชื่อร้านตามที่ตอนสั่ง) — หลังลบมี **ปุ่ม "↩️ เลิกทำ" ใน toast 10 วินาที**: กดแล้วกู้คืนร้านกลับมาเหมือนเดิมครบ (ทะเบียน/เมนู/ตั้งค่า/ติดตาม/รออนุมัติ + Firestore restaurants/menus/users) ภายใน 10 วิเท่านั้น (ผ่านเลย = ลบถาวร)
3.8 **⚠️ เตือน id ร้านซ้ำ** (แบนเนอร์บนแดชบอร์ดแอดมิน) — ตรวจตอนรวมร้านจาก Firestore: ถ้าร้านต่างชื่อ **ใช้ id เดียวกัน** (บั๊กเก่า — สมัครจากคนละเครื่องได้ id ซ้ำ → เมนูปนกัน) แบนเนอร์แดงจะขึ้นว่า id ไหนชนกับร้านไหน → กด **"🔧 แก้ไขอัตโนมัติ"** = ร้านที่ชนได้ id ใหม่ (timestamp) + **ย้ายเมนู/ค่าตั้งตาม id ใหม่** (ไม่ปนกันอีก) + สะท้อน Firestore — ระบบกันไว้ 2 ชั้นด้วย: **ร้านใหม่ได้ id จาก timestamp** (ไม่มีวันชนอีก) + **getRestaurants() กรอง id ซ้ำ** (ไม่แสดงการ์ดซ้ำ)
4. **ปุ่ม "📋 รับออเดอร์"** (มุมขวาบน สีเขียว) — เปิด Dashboard รับออเดอร์ของร้านที่เลือกอยู่ / ปุ่ม "🛵 ไรเดอร์" (สีม่วง) — เปิด Rider Dashboard / ปุ่ม "💰 การเงิน" (สีทอง) — เปิดแดชบอร์ดการเงินรวมแพลตฟอร์ม
5. **🛵 ไรเดอร์ประจำร้าน** (ใต้แถบเลือกร้าน) — เลือกไรเดอร์ (ชิปกดเปิด/ปิด) ที่จะเห็นงานของร้านนี้ — งานจากร้านนี้จะขึ้นเฉพาะไรเดอร์ในกลุ่ม (ไม่เลือก = ไรเดอร์ทุกคนเห็น) — ลงทะเบียนไรเดอร์ได้ที่ Rider Dashboard
6. **💸 ค่าธรรมเนียมร้านนี้** (ใต้ panel ไรเดอร์) — ตั้ง**อัตราเฉพาะร้าน** (%) ได้ (คิดจากยอดอาหารหลังส่วนลด ค่าส่งเป็นของไรเดอร์) — กด **"ใช้ค่าเริ่มต้น (รวม)"** = กลับไปใช้อัตรารวมจากหน้า finance — **ร้านใหม่ (สมัครภายใน 30 วัน) ได้โปรฯ ฟรีค่าธรรมเนียม 0%** ป้าย 🎉 แสดงวันหมดโปรฯ (อัตราที่ตั้งไว้จะเริ่มมีผลหลังโปรฯ หมด) — ค่าแพลตฟอร์มนี้**ลูกค้าเห็นเป็นรายการแยกตอนสั่งซื้อ** (ราคารวม = อาหาร + ค่าส่งตามระยะทาง + ค่าแพลตฟอร์ม)
7. **🛎️ สถานะรับออเดอร์ / ปิดชั่วคราว** (panel ใต้แถบเลือกร้าน — เห็นทั้งร้านค้าและแอดมิน) — badge สถานะปัจจุบัน (🟢 เปิดรับ / 🔴 ปิดชั่วคราว / นอกเวลาเปิด-ปิด) + ปุ่ม **"🔴 ปิดชั่วคราว"** (กรอกเหตุผลได้หรือเว้นว่าง — ลูกค้าเห็นเป็น tooltip) = หยุดรับออเดอร์ทันที **โดยไม่ต้องแก้วลาเปิด-ปิด** — หน้าร้านลูกค้า/ชิปร้านเปลี่ยนเป็น "🔴 ปิดชั่วคราว" + บล็อกการสั่งซื้อทันที (ข้ามแท็บ) — กด **"🟢 เปิดรับออเดอร์"** อีกครั้ง = กลับมารับตามปกติ (เก็บใน `sangkha-store-closed`) — **🤖 ปิดอัตโนมัติตามออเดอร์ค้าง**: ติ๊ก "ปิดอัตโนมัติเมื่อออเดอร์ค้าง ≥ [N] ใบ" (ค่าเริ่มต้น 5 — ตั้งได้ 1–99) — พอออเดอร์รอเตรียม (ใหม่ + กำลังเตรียม) ถึงเกณฑ์ ระบบ**ปิดรับออเดอร์เองทันที** (หน้าร้านขึ้น "🔴 ปิดอัตโนมัติ (ค้าง N ใบ)" + บล็อกการสั่ง) และ**เปิดรับเองเมื่อเคลียร์ต่ำกว่าเกณฑ์** — ป้าย/ชิปร้าน/ปุ่มสั่งแสดงสถานะอัตโนมัติ (เก็บใน `sangkha-auto-close`) — **หน้า dashboard รับออเดอร์มีแถบเดียวกัน** (ใต้แถบเลือกร้าน) กดปิด/เปิด + ตั้งเกณฑ์อัตโนมัติได้เลยโดยไม่ต้องกลับมาหน้า admin — อัปเดตสดข้ามแท็บ (ออเดอร์ค้างเปลี่ยน → สถานะเปลี่ยน)
8. **🛵 ค่าจัดส่งตามระยะทาง** (ใต้ panel ค่าธรรมเนียม) — ตั้งค่าส่งเฉพาะร้าน: **ค่าเริ่มต้น (฿) + ต่อ กม. (฿) + ส่งฟรีขั้นต่ำ (฿)** — ตัวอย่างค่าส่งคำนวณให้สด ๆ จากระยะทางของร้าน — กด "คืนค่าเริ่มต้น" = กลับไปใช้ค่าที่ตั้งตอนสมัคร — ส่งผลถึงหน้าร้านลูกค้าและตอนสั่งซื้อทันที
7.5 **🧾 ภาษีหัก ณ ที่จ่ายไรเดอร์** (panel ใต้ค่าจัดส่ง) — ตั้ง**อัตราค่าเริ่มต้น (%)** (ค่าเริ่มต้น 3% — หักจากรายได้ไรเดอร์ตอนคำนวณสลิปรายเดือน) + **กฎอัตราพิเศษ**: เลือก **ร้าน** (ทุกที่ / ร้านเฉพาะ) + **อัตรา %** + **ช่วงเวลาเริ่ม–สิ้นสุด** (เว้นว่างได้ = ไม่จำกัด) → **"＋ เพิ่มกฎ"** — กฎเฉพาะร้านชนะกฎทุกที่ / ช่วงเวลาที่ระบุชนะไม่จำกัดช่วง / ไม่ตรงกฎไหน = ค่าเริ่มต้น — badge แสดง "ร้านนี้ตอนนี้หัก X%" ตามร้านที่เลือกอยู่ — ลบกฎได้ด้วย 🗑️ — สลิปไรเดอร์คำนวณอัตราต่อใบตาม**ร้าน + เวลาที่ส่งเสร็จ**ของงานนั้น
8. **โฆษณา (สไลด์บนสุด)** — ด้านล่างรายการสินค้า:
   - **＋ เพิ่มโฆษณา** → เลือกไอคอน (อีโมจิ — หรือ**โหลด/ถ่ายรูปสินค้าจริงแทนไอคอน** ได้: สไลด์บนสุด/การ์ดดีลแสดงรูปสินค้าขอบขาวลอยแทนอีโมจิ), **แอนิเมชันหัวข้อ** (กระพริบ / วิ้งเข้า-ออก / เด้งขึ้นลง / โยกซ้าย-ขวา / ซูมวิ้ง / ไม่มี — แสดงที่สไลด์บนสุด + การ์ดดีลเด็ด + **ชิปดีลเด็ดในแถบเมนู** + หน้าโปรโมชันเต็ม), หัวข้อ, ปุ่มข้อความ, รายละเอียด, สีพื้นหลัง (6 แบบ), **ชื่อคลิปวิดีโอ** (วาง `ชื่อคลิป.mp4` / `.webm` ไว้ในโฟลเดอร์ — เว้นว่าง = ใช้พื้นสี + อีโมจิ), **เงื่อนไขโปรโมชัน** (คั่นแต่ละข้อด้วย `|`), **✨ แบนเนอร์ AI** (กด "AI วาดแบนเนอร์" — AI วาดภาพพื้นหลังตามหัวข้อ+รายละเอียดโฆษณา ฟรี ไม่ต้องใช้คีย์ — ใช้แทนพื้นสีไล่ gradient โดยสีที่เลือกยังเป็นตัวสำรอง — **ใส่รูปจริงได้** (รูปสินค้า/โลโก้: กดช่อง "📷 รูปจริงที่จะประกอบ" — ระบบประกอบรูปจริงลงบนแบนเนอร์เป็นกรอบกลมมุมมน + วงแหวน + เงา + ป้าย "โปรโมชัน" ดูเป็นโฆษณามืออาชีพในภาพเดียว) + **ช่อง "✍️ ข้อความ/โจทย์ให้ AI"** (พิมพ์โจทย์เพิ่ม เช่น "เบอร์เกอร์ชีสกับเฟรนช์ฟรายส์ บนโต๊ะไม้โทนอบอุ่น" — AI วาดพื้นหลังตามนี้) + **ติ๊ก "🎬 เจนเป็นภาพเคลื่อนไหว"** → โฆษณาเล่นแบบซูม/พาโนรามา (Ken Burns) + แสงวิ่งผ่าน (ดูเป็นคลิปโฆษณา ใช้ CSS animation — ไม่ต้องมีไฟล์คลิป) — **ครอบคลุมทุกจุด**: สไลด์บนสุด (เพิ่มตัวหนังสือเด้งเข้าฉาก), **การ์ดดีลเด็ดในแถวเมนู (ad-card)**, **หน้าโปรโมชันรวม deals.html (deal-card)**, และ **หน้าโปรโมชันเต็ม deal.html (ฮีโร่ + ตัวหนังสือเด้งเข้าฉาก)** — โฆษณาเดิมไม่มี field นี้ = ภาพนิ่งเหมือนเดิม — เคารพโหมดลดการเคลื่อนไหว (ปิด animation ให้อัตโนมัติ) — มีปุ่ม "🎨 ปรับภาพเดิม" วาดใหม่ด้วย seed เดิม+1,+2,... ให้ภาพใกล้เคียงแต่ต่างกันจริง กดซ้ำได้เรื่อย ๆ — เลือกแบบปรับได้: สีสดขึ้น / ใกล้ขึ้น / พื้นหลังสะอาดขึ้น / แสงสวยขึ้น / จัดองค์ประกอบสวยขึ้น หรือสลับไปเรื่อย ๆ), **คูปองส่วนลด** (ประเภท: เปอร์เซ็นต์ / จำนวนเงิน / ส่งฟรี / ไม่มี + มูลค่า + ขั้นต่ำการสั่งซื้อ), และ **🕐 เวลาออกอากาศ** (เริ่ม/สิ้นสุด — เว้นว่าง = ออกตลอด) พร้อมปุ่ม **⚡ ตั้งเร็ว** (1 ชม. / 1 วัน / 1 สัปดาห์ / 1 เดือน / ✕ ล้าง — กดคลิกเดียวเริ่มทันที + สิ้นสุดอัตโนมัติ) — การ์ดโฆษณาแสดงป้าย 🟢 กำลังออกอากาศ / 🟡 รอเริ่ม (เวลาที่เริ่ม) / 🔴 หมดอายุ (เวลาที่สิ้นสุด) + ป้าย 🎟️ สรุปคูปอง
   - **✏️ / 🗑️** แก้ไข/ลบโฆษณา — ส่งผลถึงสไลด์บนสุดและโฆษณาแทรกเมนูในหน้าร้านลูกค้าทันที
   - **👆 สถิติคลิก** — ทุกการ์ดโฆษณาแสดงจำนวนคลิก (นับทุกครั้งที่กดสไลด์/ปุ่ม CTA บนหน้าร้าน **รวมทั้งหน้ารวมดีลเด็ด**) + รวมคลิกทั้งหมดด้านบน — ดูว่าโฆษณาไหนดังสุด
9. **⭐ รีวิวจากลูกค้า** (ส่วนล่างสุด) — รีวิวของร้านที่เลือก (เรียงใหม่สุดก่อน): ดาว, ชื่อลูกค้า, วันที่, ข้อความรีวิว + หัวข้อแสดงคะแนนเฉลี่ย และปุ่ม **"💬 ตอบกลับรีวิวนี้"** — พิมพ์คำตอบส่งได้ (แก้ไข ✏️ / ลบ 🗑️ ได้ทีหลัง) — รีวิวอัปเดตสดเมื่อลูกค้าส่งในแท็บอื่น

**สำคัญ:** สินค้าที่เพิ่ม/แก้/ลบ ที่นี่ **ส่งผลถึงหน้าร้านลูกค้าทันที** (ข้อมูลแชร์กัน)

**ลองทำ:**
- กด "＋ เพิ่มสินค้า" → เพิ่มเมนูใหม่ → เปิดหน้าร้านลูกค้า (`/`) แล้วสลับไปร้านเดียวกัน → เห็นเมนูใหม่

## 5.5) 🔥 Firebase (App + Auth + Firestore — พร้อมใช้ทุกหน้า)

แอปหลักยังทำงานแบบ localStorage (ไม่มี backend) — แต่มีชั้นเชื่อม **Firebase** สำเร็จรูป (App + Auth + Firestore) โหลดจาก CDN (ไม่ต้องติดตั้ง/build) เปิดใช้ได้ใน ~5 นาที:

1. ไปที่ [console.firebase.google.com](https://console.firebase.google.com) → สร้างโปรเจกต์ → เพิ่มแอปแบบ **Web** → จดค่า config
2. เปิด **Firestore Database** → สร้างฐานข้อมูล → **โหมดทดสอบ** (test mode 30 วัน)
3. วางค่า config ใน `firebase-config.js` (apiKey ต้องไม่เหลือ `AIza...` placeholder — ระบบตรวจอัตโนมัติ)
4. โหลดหน้าใหม่ — **ทุกหน้า** auto-init ให้ Firebase พร้อมใช้ (App + Auth + Firestore) — หน้า **Dashboard รับออเดอร์** จะมี badge 🔥 และ**ฟังออเดอร์สดจาก Firestore ด้วย `onSnapshot`**: ลูกค้าสั่งจากเครื่อง/เบราว์เซอร์ไหนก็ได้ → ออเดอร์เด้งขึ้น dashboard ทันที (และอัปเดตสถานะออเดอร์สะท้อนกลับ) — localStorage ยังเป็นแคช (ทำงานต่อแม้เน็ตหลุด)

**SDK ที่โหลด:** `firebase-app` + `firebase-auth` + `firebase-firestore` (compat 10.12.2) — โหลดเฉพาะที่ใช้งาน (storage/messaging ยังไม่ใช้ ไม่โหลดให้เปลือง) — `initializeApp` ถูกเรียก**ครั้งเดียว** (guard `firebase.apps` + singleton promise — กัน "Firebase App already exists")

**ใช้งานจากหน้า HTML:** ทุกหน้าโหลด `firebase-config.js` → `firebase-lib.js` → `menu-data.js` → สคริปต์หน้า เรียงลำดับถูกต้องอยู่แล้ว — เรียกใช้ผ่าน `window.FirebaseOrders`:

```js
await window.FirebaseOrders.init(); // คืน true เมื่อพร้อม (เรียกซ้ำได้ — ได้ promise เดียวกัน)
FirebaseOrders.isReady;  // true = พร้อมใช้
FirebaseOrders.db.collection("orders").get();           // Firestore ตรง ๆ
FirebaseOrders.auth.signInWithEmailAndPassword(em, pw);  // Auth ตรง ๆ
FirebaseOrders.onAuthChange((user) => ...);              // ฟังสถานะล็อกอิน
```

**โครงสร้าง Firestore (5 คอลเลกชัน — สร้างอัตโนมัติเมื่อใช้งาน):**

| คอลเลกชัน | doc id | ข้อมูล | เขียนเมื่อไหร่ |
|---|---|---|---|
| `users` | uid (`cust-<เบอร์>` / `rest-<id>` / `<riderId>`) | name, phone, role (customer/restaurant/rider/admin), status, createdAt | ลูกค้าสั่งซื้อ / สมัครร้าน / ลงทะเบียนไรเดอร์ |
| `restaurants` | restaurantId | name, address, phone, latitude, longitude, status, rating (+cuisine, open/close, coverEmoji, coverBg, **imageUrl**, deliveryFee, createdAt) | สมัครร้านใหม่ / แอดมินแก้ข้อมูลร้าน |
| `menus` | `<restaurantId>-<menuId>` | name, price, **imageUrl**/image, emoji, desc, color, category, status | เมนูผ่านอนุมัติ (setMenu) |
| `orders` | เลขออเดอร์ | customerId, restaurantId, riderId, items, total, deliveryFee, status, createdAt (+customer, delivery, discount, platformFee, gps) | สั่งซื้อ / เปลี่ยนสถานะ / ลบ |
| `riders` | riderId | name, phone, vehicle, status, latitude, longitude (+email, joinedAt) | ลงทะเบียน / แก้ชื่อ-เบอร์-อีเมล |

**สิ่งที่ซิงก์ (write-through — localStorage ยังเป็นแคชหลัก ทำงานต่อแม้ไม่มีเน็ต):**
- สั่งซื้อ (`addOrder`) / เปลี่ยนสถานะ (`updateOrderStatus`) / ลบออเดอร์ (`deleteOrder`) → `orders` + สร้าง/อัปเดต `users` ของลูกค้า
- สมัครร้าน (`addRegisteredStore`) / แอดมินแก้ข้อมูลร้าน (`setStoreEdit`) → `restaurants` + `users` (role: restaurant)
- เมนูผ่านอนุมัติ (`setMenu`) → `menus`
- ลงทะเบียน/แก้ไรเดอร์ (`registerRider` / `updateRider*`) → `riders` + `users` (role: rider)

**ฟังสดข้ามเครื่อง (onSnapshot — ทุกหน้า auto-init):**
- Dashboard: ออเดอร์จากเครื่องไหนก็ได้ → เด้งขึ้นทันที (badge 🔥)
- ทุกหน้า (`initFirebaseCollections`): ฟัง `restaurants` + `riders` + `menus` → **ร้านที่สมัคร/ไรเดอร์ที่ลงทะเบียน/เมนูที่เพิ่มจากเครื่องอื่นจะโผล่ที่เครื่องนี้** (หน้าร้าน: ชิปร้านใหม่ + เมนูสด / admin: dropdown + whitelist + รายการสินค้า / rider: แถบไรเดอร์)
- **เมนู (หน้าร้าน/หลังร้าน):** เมื่อตั้งค่า Firebase แล้ว **อ่านเมนูจาก Firestore เป็นหลัก** (`getAll("menus")` ตอนเริ่ม + ฟังสด `menus`) — ร้านเพิ่ม/แก้เมนูแล้วอนุมัติ → ลูกค้าอีกเครื่องเห็นทันที; ถ้า Firestore ใช้ไม่ได้ (ไม่มี config/เน็ตหลุด) fallback กลับ localStorage/defaultMenu เหมือนเดิม (`getMenu` → แคช Firestore → localStorage → defaultMenu) — ถ้าแท็บที่เลือกไม่มีเมนูแต่ร้านมีเมนูหมวดอื่น หน้าเปลี่ยนแท็บให้อัตโนมัติ (เห็นเมนูทันที)
- ครั้งแรกที่เชื่อม: **seed ข้อมูล localStorage ปัจจุบันขึ้น Firestore อัตโนมัติ** (เฉพาะคอลเลกชันที่ยังว่าง — ไม่ทับข้อมูลที่มีอยู่)

**🔐 Security Rules (สิทธิ์รายบทบาท):** ไฟล์ **`firestore.rules`** (root โปรเจกต์) — ผู้ใช้แก้โปรไฟล์ตัวเอง, แอดมินดูทั้งหมด, ร้านแก้ร้าน/เมนูตัวเอง, ลูกค้าอ่านร้าน/เมนู + เห็นออเดอร์ตัวเอง, ไรเดอร์แก้ข้อมูลตัวเอง + เห็นงานที่รับ — อธิบายครบทุกส่วนใน **`FIRESTORE_RULES.md`** (อิง Firebase Auth: users doc id = auth uid, restaurants.ownerId, orders.customerId/restaurantId/riderId, riders doc id = riderId — แอดมิน = custom claim `admin: true` หรือ users role == 'admin') — ⚠️ ยังไม่ได้ต่อ Firebase Auth → ยังคงใช้โหมดทดสอบจนกว่าจะต่อ Auth แล้วค่อย deploy rules

**หมายเหตุ:** ระบบล็อกอินเดิม (PIN ใน localStorage) ยังใช้เหมือนเดิม ไม่ถูกแตะ — `FirebaseOrders.auth` พร้อมใช้เมื่อต้องการเปลี่ยนไปใช้บัญชีอีเมลจริงทีหลัง

**ไม่ตั้งค่า = ไม่มีผลอะไร** — ทุกหน้าใช้โหมดท้องถิ่นเหมือนเดิม 100% (ไม่โหลด SDK ไม่ error สะพานเชื่อมข้ามไปเงียบ ๆ)

## 6) หมายเหตุ

- **🚀 Deploy ขึ้น GitHub Pages อัตโนมัติ (GitHub Actions):** ไฟล์ **`.github/workflows/deploy.yml`** — ทุกครั้งที่ push ขึ้น branch `main` ระบบจะอัปโหลดเว็บขึ้น GitHub Pages ให้อัตโนมัติ (เว็บเป็น static ล้วน ไม่ต้อง build) — ตั้งครั้งเดียว: repo → **Settings → Pages → Source: "GitHub Actions"** → push ครั้งถัดไปเว็บจะขึ้นที่ `https://คุณ.github.io/ชื่อrepo/` เอง — กดปุ่ม "Run workflow" ในแท็บ Actions ก็ได้ถ้าอยาก deploy มือ — เปิดดูสถานะได้ที่แท็บ **Actions** (วงกลมเขียว = สำเร็จ)
- **โฆษณาบนสุด:** โฆษณาแต่ละชิ้นสามารถมีคลิปวิดีโอของตัวเองได้ (ตั้งชื่อคลิปในหน้า admin เช่น `pizza-clip` → วาง `pizza-clip.mp4`/`pizza-clip.webm` ในโฟลเดอร์) — ถ้ายังไม่มีไฟล์คลิป จะแสดงพื้นสี + อีโมจิแทนอัตโนมัติ
- **เพิ่มร้านค้าใหม่:** ไปเพิ่มที่ array `RESTAURANTS` ใน `menu-data.js` (ชื่อ, คะแนน, เวลา, ระยะทาง, เมนูเริ่มต้น) — หน้าร้านและหน้า admin จะโผล่ให้อัตโนมัติ
- หน้าเว็บเป็น HTML/CSS/JS ล้วน ไม่มี library ภายนอก ไม่ต้อง `npm install`
